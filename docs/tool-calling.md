# Tool Calling

sarashina3-mini と sarashina3-nano が、Chat Completions の Tool Calling（モデルが関数を呼ぶ仕組み）をどこまで扱えるかを、偽のツールと 8 つの場面で確かめた結果。測った日付と条件は [method.md](method.md) にある。

| `tool_choice` の指定 | 最後まで答えた会話 | 往復の上限で打ち切り | 送信の数（mini / nano） |
|---|---|---|---|
| 省く | 0/16 | 15/16 | 40 / 38 |
| `auto` を明示 | 16/16 | 0/16 | 16 / 17 |
| 最初の往復だけ `required` | 13/16 | 0/16 | 15＋送り直し 3 / 18 |

会話の数は、8 つの場面 × 2 モデル。往復の上限は 5 回。

## 使うときに決めること

分かったこと:

- **`tool_choice: "auto"` を必ず明示する。** 省くと、モデルはツールを呼び続けて答えを返さない
- `auto` を明示すれば、両モデルとも 8 つの場面をすべて最後まで答えた

公式の文書には、`tool_choice` を省くと、ツールを渡したときは `required`（必ずツールを呼ぶ）になると書かれている。実際にそのとおりで、ツールの結果を返しても毎回またツールを呼び、答えの文を一度も返さなかった。たとえば nano は、天気を 1 回聞くだけの問いで、同じ引数（ほしぞら市、2026-10-14）の `get_weather` を 5 回呼び、2 回目には同じ呼び出しを 2 つ並べた。ツールが要らない問いでも、mini は 5 回、nano は 9 回ツールを呼んだ。

OpenAI の API では、`tool_choice` を省いたときの既定は `auto`（呼ぶかどうかをモデルが決める）である。OpenAI 向けのコードをそのまま Sarashina に向けると、この違いで会話が終わらなくなる。

## `auto` を明示したときの振る舞い

分かったこと:

- ツールの選び方、引数、結果を使った答えのどれにも問題が無かった
- 存在しない URL や都市には、作り話をせずに「取得できなかった」と答えた

引数は JSON として正しく、都市名や日付も合っていた。ツールが要らない問いではツールを呼ばずに答えた。存在しない URL には「404 で取得できなかった」、存在しない都市には「その都市の情報は無い」と答えた。

2 つのツールが要る問いの解き方は、モデルで違った。mini は 1 回の応答で天気と Web を並べて呼び、2 往復で答えた。nano は 1 つずつ呼んで 3 往復かかった。

## `required` を明示したときの時間切れ

分かったこと:

- 最初の往復だけ `required` を明示すると、mini が 60 秒以内に応答を返さないことが 3 回あった
- nano ではこの条件でも時間切れは無かった

天気を 1 回聞く問いで 1 回（送り直すと返った）、天気と Web の両方を使う問いで 2 回続けて（送り直しても返らなかった）。同じ問いでも、`tool_choice` を省いた条件（既定は `required` のはず）では応答が返っていた。値を明示したときだけ応答が返らなくなる理由は、文書からは分からない。

この条件の残りの失敗 2 件は、ツールが要らない問いで 1 往復目にツールを強制したもので、呼ぶのは当然である（条件の作りによる失敗）。

Chat の 61 問でも、mini は 1 回 60 秒の時間切れを起こしている（[speed-and-limits.md](speed-and-limits.md)）。合わせると、同じ日の mini の時間切れは 4 回、nano は 0 回だった。mini を使うなら、時間切れを前提にした送り直しの設計が要る。

## 試した場面とツール

ツールは本物の通信をせず、決まった結果を返す偽物にした。返す内容（架空のお店・記事・天気）は、この検証のために作ったものである。

| ツール | 返すもの |
|---|---|
| `web_fetch` | 架空のお店のお知らせと、架空の記事 |
| `get_weather` | 架空の 2 都市の天気 |
| `calculator` | 四則演算の結果 |

場面は 8 つ: 天気を 1 回聞く、Web のお知らせから抜き出す、記事を要約する、天気と Web の両方を使う、天気の結果で計算する、ツールが要らない問い、存在しない URL、存在しない都市。

## まだ確かめていないこと

- `required` を明示したときの時間切れが、決まった条件で必ず起きるのか（3 回目は送っていない）
- 60 秒より長く待てば応答が返るのか
- ツールが多い場合（今回は最大 3 つ）や、長いツールの結果を返した場合の振る舞い
